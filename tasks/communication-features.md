## Design boundaries

Role mention tokens use `<@&ROLE_ID>`, resolved against the current authorization lease. Names are presentation, not identifiers. Mentionable defaults off; MentionEveryone permits a scoped override. Membership does not bypass ViewChannel. Expose no recipient roster in chat metadata.

Polls belong to an accessible message/conversation. User IDs and scope come from authenticated server state. Do not store plaintext poll content alongside otherwise encrypted chat history. One authenticated user has one replaceable ballot, with validated option IDs; close and voting must serialize.

Private conversations and calls require their own membership model. A call does not move users into a hidden voice channel. Invitation acceptance is separate from media capture. Participant removal revokes delivery and rotates encryption keys. Server policy and client blocks apply before ringing.

Media encryption is a complete protocol integration, not an encryption badge over ordinary SRTP. Current SFU payload inspection and FFmpeg recording require explicit changes. Reuse a maintained, reviewed protocol/library where supported; do not invent a custom group cryptosystem. Recording policy is awaiting the user's answer to the presented options.

Position data is opt-in and scoped to authorized voice peers. Game integration must use a bounded local input with explicit enablement; no network listener or game-process inspection by default.
