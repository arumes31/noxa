# Role replacement implementation checkpoint

Updated 2026-09-22. This is a fresh-version release: production entrypoints claim an empty PostgreSQL database for roles-v1 and reject unmarked databases with existing tables. No old database, account or permission migration is part of launch. Startup requires an active roles-v1 policy and the client requires a roles-v1 handshake. This is an implementation checkpoint, not a completion notice. Dated sections below describe earlier incremental work, not the current launch plan.

The historical group and numeric-permission storage, privilege-token paths and desktop controls have been retired. Fresh schema initialization ends without those tables or columns. Remote single-ID/global complaint deletion, raw log export and process stop/restart are explicitly retired.

The server and offline operator commands use a database-wide process lease. Registered native/integration admission refreshes Authority if stored membership changed at the same revision. The single-new-member fast path requires no live native session and no capability revocation; other changes fully reconcile. Integration admission is revalidated after refresh. Abrupt loss of the dedicated lease connection leaves a brief detection window, so operators must verify the server process has stopped before writing.

## Explicit policy choices to keep visible

- Audit history with no trusted scope is visible only to owner/Administrator. Redacted rows expose ID/time only to preserve pagination. Channel-scoped records require visibility of every referenced channel, including prior parents; deleted scopes remain protected from ordinary audit readers.
- Hidden custom children are flattened in a recipient's tree when their parent is not visible.
- ViewConnectionInfo also controls visibility of invisible presence in role snapshots/events; its English/German catalog labels now explicitly describe both effects.
- Avatar lookup follows live member visibility: self lookup remains available, but knowing a hidden or offline third-party unique ID does not grant access to the stored avatar. Server branding is separate server-wide presentation data.
- Server-side recordings require a registered account; the recording remains tied to that account's permissions, not the current connection or a synthetic recorder identity.
- Every queued channel event carries a server-internal scope envelope that is stripped only by the authorized socket writer. Unwrapped non-direct chat and retired/unknown events fail closed in role mode.
- Server mute/deafen apply to the connected session, persist across channel moves, and clear on disconnect. They do not rewrite a member's own local mute/deafen preferences. Moderators need the current target channel capability and higher rank to clear either flag too.
