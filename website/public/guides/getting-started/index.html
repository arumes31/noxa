Using noXa · Public alpha

Get started with the Windows client

Download noXa, connect to a community, verify its identity, and find your first conversation.

On this page

  1. Download the desktop client
  2. Connect to your server
  3. Choose what this device remembers
  4. Find your community
  5. Keep the client current

1. Download the desktop client

The published desktop download is for Windows x64. noXa is a public alpha: use matching current client and server versions, and keep important data backed up.

  1. Download the Windows x64 client from the project’s GitHub release.
  2. Read the release notes for that version, then launch the executable.
  3. Ask your community’s operator for the server hostname, account details or guest admission policy, and the server certificate fingerprint.

Upgrade the server first. Current clients require the updated server’s login challenge. Against an older server they report that it needs an update and do not fall back to the old sign-in. Encrypted direct messages, private groups, and channel media require the server’s database and control-channel TLS.

The desktop interface uses its native application bridge. Opening the desktop frontend files in a browser is not a substitute for the Windows client. For browser access, use the separate PWA guide.

2. Connect to your server

  1. Enter the server address. The default desktop control port is 12333; a local installation uses localhost:12333. Your operator may provide a different port.
  2. Enter your Account login / guest name. For a password account, enter its Account password.
  3. If the server requires a join password, enter that separately. A server password and an account password serve different purposes.
  4. Optionally enter a Display name. This changes the name others see, while the account login, identity, and roles remain the same.
  5. Connect and compare the server certificate fingerprint with the value supplied through a trusted channel by the operator before trusting it.

Trying the public test server? The desktop address is wowcraft.pw. It is a public alpha test environment; access and availability can change. Use your community’s own address for its private server.

A new installation starts with empty connection fields. The last successful connection can prefill the server, account, and optional display name. Bookmarks can keep separate community connection details.

3. Choose what this device remembers

Under Optional details, Remember passwords for this connection is an opt-in choice for each server and account pair. On Windows, saved account and server passwords are stored separately from settings and protected by Windows DPAPI for the current OS account.

Uncheck the option to delete that pair’s saved passwords immediately. A failed connection does not replace the last successful profile or its stored passwords. Only enable remembering on a device and OS account you control.

To change your public name while connected, use Self → Change display name. Live name changes require a compatible server; they do not change your account credentials or permissions.

4. Find your community

The channel tree and community members help you find a conversation. Open a channel’s chat or a direct-message conversation, then use the chat tabs to return to it. Multiple server tabs keep connections separate.

New self-hosted installations begin with closed access rules. If you can connect but cannot see a channel, ask an operator to check your roles and the channel’s saved access policy. An empty channel list is not always a connection failure.

Use the voice and sharing guide to set up your microphone, or the chat guide for messages, threads, and saved items.

5. Keep the client current

The desktop updater separates downloading, verification, installation, and restart. It verifies the release’s signed manifest with embedded trusted keys. A download can be cancelled before verification begins.

Restart now keeps the current application open until the replacement confirms startup. If that supervised startup fails, the updater restores the previous executable; it does not roll back settings, identity, or chat history. A uniquely named .noxa-previous-*.exe is retained beside the executable for manual recovery.

This automatic recovery covers the supervised restart, not a later manual launch after you close the app. Read release notes and coordinate server-first upgrades with the operator. Keep your identity backup safe before changing devices or removing the application.
